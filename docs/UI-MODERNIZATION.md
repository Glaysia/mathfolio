# 현대적인 UI와 네이티브·WASM 공통 편집 화면 계획

2026-10-23 갱신. 현재 기능과 수정된 [스크롤 성능](PERFORMANCE.md)을 기준선으로 삼는다. Excalidraw처럼 문서 중심의 간결하고 현대적인 화면을 만들며, 같은 Rust 화면을 네이티브 독립판과 Obsidian·VS Code의 WASM 내장에서 사용한다. 아래 1차 구현과 남은 계획을 구분하며 전체 내장 완료를 뜻하지 않는다.

**구조의 단일 기준은 [네이티브·WASM 계획](NATIVE-WASM.md)이다.** 독립 실행판에는 JS/TS 실행 엔진·Electron·Chromium·WebView를 넣지 않는다. UI는 Rust egui로 유지하고 TS는 별도 플러그인의 WASM·호스트 연결에만 사용한다. 이 문서는 그 구조 안에서 화면·도움말·입력을 어떻게 개선할지 다룬다.

## 방향

**1차 구현:** [0212](analysis/0212-shared-native-chrome.md)에 간결한 헤더/작성 도구·선택 속성·테마·검색 도움말과 입력 격리, native 글꼴 공급 경계 및 양 OS 회귀 결과를 기록했다. 기존 키를 유지한다. WASM/Worker·호스트 IO 분리와 두 플러그인 검증은 남아 있으며, 실제 창 비교에서 관찰한 추가 그리기 비용도 같은 기록에 공개한다.

Excalidraw처럼 작업 내용이 중심이 되는 간결하고 현대적인 화면으로 개선한다. 참고 대상은 [Excalidraw](https://github.com/excalidraw/excalidraw)의 제품 경험이며, Mathcraft는 Rust 기반의 공학 계산 워크시트와 정밀한 수식 조판을 유지한다.

기존의 Prime 외형 재현 방침을 UI 표현층에서 대체한다. 수식 편집 의미, 계산 확정, 단위, 문서 형식과 기존 단축키는 계속 호환 기준으로 삼는다. 계산·문서·편집의 Rust 구현을 재사용하고, UI를 호스트 창과 분리된 편집 컴포넌트로 만든다. 플러그인 프로젝트는 별도로 유지하되 내장 가능성은 이번 UI 설계 단계에서 검증한다.

## 내장 가능한 구조

현재 [eframe 0.36.2는 native 실행과 WebRunner/WASM 경로를 제공한다](https://docs.rs/eframe/0.36.2/eframe/). Rust·egui 화면을 공통으로 유지하고 WebRunner로 내장한다. 2026-10-24 [WASM SDK](WASM-SDK.md)의 실제 Canvas·Worker 실행과 bytes 저장 왕복을 검증했다. 두 플러그인 연결은 별도 레포에서 검증한다. 실제 편집 표면을 브라우저와 두 호스트에 올려 입력·스크롤·글꼴·수명 주기를 먼저 확인한다. 호스트 제약은 어댑터에서 해결하며 독립판에 웹 엔진을 도입하거나 TS 편집기를 별도로 만들지 않는다.

| 계층 | 책임 |
| --- | --- |
| Rust 공통 계층 | 문서·수식 편집, 계산·단위, 확정·Undo/Redo, 저장 표현과 조판 데이터 |
| 내장 편집 컴포넌트 | 문서 canvas, 선택·포커스, 도구 모음·속성·도움말, 호스트와 독립적인 열기/수정/상태 전달 |
| standalone 어댑터 | Windows/Kubuntu 창, 파일 선택·저장·인쇄와 OS 연동 |
| Obsidian 어댑터 | 편집 View와 노트 미리보기, Vault IO, 테마·크기·포커스와 컴포넌트 해제 |
| VS Code 어댑터 | Custom Editor/Webview, workspace IO·저장/복구·Undo, 테마·크기·포커스와 컴포넌트 해제 |

첫 검증에서 OS 경로를 읽는 글꼴 로더, `rfd` 파일 대화상자, 직접 파일 IO, native 계산 thread와 인쇄 경로를 분리한다. 컴포넌트는 호스트가 전달하는 문서 bytes·글꼴·설정과 작업 결과를 사용한다. 웹에서는 같은 계산 엔진을 별도 Worker에서 실행하고 실제 중지·낡은 결과 폐기·복구를 검증한다. 호스트 경계를 통해 매 프레임 전체 문서 JSON을 왕복시키지 않는다. 세션 소유권·저장 승인·프로토콜과 단계별 통과 조건은 [구조 계획](NATIVE-WASM.md)을 따른다.

## 화면 구성

| 영역 | 계획 |
| --- | --- |
| 작업 공간 | 문서에 충분한 공간을 주고 배경·여백·페이지 경계를 차분하게 정리한다. A4와 오른쪽 초과 영역의 기존 의미를 유지한다. |
| 주요 도구 | 열기·저장·Undo/Redo·계산과 수식·텍스트·표·도표 진입점을 간결한 도구 모음에 배치한다. |
| 문맥 속성 | 선택한 수식·텍스트·표·도표의 속성만 일관된 패널에서 보여준다. 기존 명령 핸들러에 연결한다. |
| 상태 안내 | 편집 중·확정·계산 중·Pending·오류·저장 상태를 구분하고, 상태가 바뀌어도 문서 배치를 흔들지 않는다. |
| 시각 체계 | 간격·색·아이콘·모서리·글자 크기를 공통 토큰으로 관리한다. 수식의 기준선·분수·첨자와 고해상도 글꼴을 유지한다. |
| 접근성 | 읽을 수 있는 대비, 충분한 클릭 영역, 보이는 키보드 포커스와 버튼 이름을 제공한다. |

밝은/어두운 테마와 고해상도 수식 조판을 공통 시각 체계에 포함한다. 내장 시 호스트 테마와 container 크기에 대응한다.

[호스트 테마 연동](HOST-THEMES.md)에 의미별 색·버튼 전경/배경·선택·고대비·UI 글자 크기를 받는 Rust 계약과 `호스트 따르기 / 밝게 / 어둡게 / Nord` 옵션을 구현했다. 실제 CSS 변수 수집과 설정 저장은 각 플러그인 레포에서 연결한다. 문서 원래 색은 UI 테마로 바꾸지 않는다.

## 단축키 안내

**기존 단축키를 바꾸지 않는다.** 특히 `Ctrl+-`는 이름의 문자 아래첨자 의미를 유지하며 확대·축소로 재배정하지 않는다. 현재 편집 문맥과 IME 처리도 유지한다.

버튼·메뉴·단축키 도움말이 같은 명령 목록을 사용하도록 정리한다. 목록에는 명령 이름, 기존 키 조합, 적용 문맥, 간단한 설명과 비활성 이유를 담는다. 플랫폼별 표기는 실제 입력 처리와 일치시킨다.

- 버튼 툴팁에 명령 이름·기존 단축키·짧은 사용 예를 함께 표시한다.
- 검색 가능한 명령·단축키 안내 화면을 제공한다. 여는 버튼을 두며 새 전역 단축키는 임의로 지정하지 않는다.
- 수식 편집, 영역 선택, 표 셀, 도표 입력처럼 문맥이 달라지는 키는 적용 조건을 설명한다.
- Enter 확정, Space 선택 확장, 행렬 Tab, 이름 아래첨자는 작은 수식 예제로 안내한다.
- 비활성 명령은 실행할 수 있는 선택·문맥을 알려준다. 구현되지 않은 기능을 실행 가능한 것으로 표시하지 않는다.
- Obsidian·VS Code에 내장되면 편집 표면이 포커스를 가진 동안 처리한 키만 소비한다. 기존 키 정의를 유지하고 활성 영역의 소유권으로 호스트와의 충돌을 조정한다. 검색·도움말·속성 입력이 수식 키와 전역 명령을 동시에 실행하지 않게 한다.

## 옵시디언 내장 검증

Obsidian은 [공식 API](https://github.com/obsidianmd/obsidian-api/blob/master/obsidian.d.ts)에 custom View 등록과 Markdown code block 렌더링을 제공한다. 작은 어댑터 시제품에서 독립된 계산서 편집 View와 노트 안의 읽기 전용 미리보기를 먼저 연결한다. 파일은 [Vault API](https://docs.obsidian.md/Plugins/Vault)를 통해 읽고 저장한다.

같은 컴포넌트가 container 크기 변경·테마 변경·포커스 전환에 대응하고, 닫힐 때 이벤트·timer·렌더러·worker를 해제하는지 확인한다. 여러 노트나 탭을 열어도 편집 상태가 섞이거나 화면 밖 미리보기가 계속 전체 frame을 그리지 않도록 한다. 문서 내부 스크롤과 노트 바깥 스크롤의 소유권도 검증한다.

## VS Code 내장 검증

[Custom Editor API](https://code.visualstudio.com/api/extension-guides/custom-editors)의 바이너리 문서 경로로 공통 WASM 화면을 연결한다. workspace 파일 IO·Save/Revert/Backup·Undo/Redo를 Rust 세션에 연결하고, 중복 이력이나 두 쓰기 세션을 만들지 않는다. Webview CSP·WASM/Worker 자산 로딩·호스트 단축키·분할 뷰·숨김/복원·종료 복구를 실제 Desktop에서 확인한다. Obsidian과 같은 SDK를 사용하며 호스트별 플러그인은 별도 프로젝트로 유지한다.

## 진행 순서

1. 수정된 native 스크롤·기능 기준선과 library 추출을 검증한다.
2. 공통 세션·bytes IO·호스트/계산 작업 경계를 나누고 native 회귀를 통과한다.
3. 실제 공통 화면의 WASM·Worker 실행과 Obsidian/VS Code 최소 어댑터를 검증한다.
4. 기존 명령·키 목록, 공통 시각 토큰과 전체 정보 구조를 정한다.
5. 주요 도구·문맥 속성·상태·검색 도움말·툴팁을 작은 변경 단위로 적용한다. 같은 명령과 Undo 경로를 사용한다.
6. Windows·Kubuntu 독립판과 두 Desktop 호스트에서 같은 문서·입력·스크롤·저장·해제를 검증한다.

상세 산출물과 단계별 통과 조건은 [네이티브·WASM 실행 순서](NATIVE-WASM.md#실행-순서와-단계별-통과-조건)를 따른다.

## 완료 기준

주요 기능을 화면에서 찾을 수 있고, 버튼과 도움말에서 기존 단축키를 확인할 수 있어야 한다. UI 개편 전후에 같은 입력은 같은 수식·단위·계산 결과·저장 내용을 만들고 Undo/Redo로 복원되어야 한다. 도구 모음과 패널 때문에 문서의 클릭 좌표나 키보드 포커스가 어긋나지 않아야 한다.

Windows와 Kubuntu의 standalone 앱, Obsidian·VS Code Desktop 내장 표면에서 크기·DPI·테마·포커스·스크롤 처리가 맞아야 한다. 계산서 편집과 노트 미리보기에서 공통 구현을 재사용하고, 내장 때문에 별도의 계산 엔진이나 키 의미가 생기지 않아야 한다. 독립판의 웹 엔진 부재와 [구조 계획의 의미·수명·성능 기준](NATIVE-WASM.md#검증과-완료-기준)을 확인하며, [스크롤 성능 기준](PERFORMANCE.md)을 UI 변경마다 유지한다.

사용자가2026-10-23 GUI 사용 금지를 해제했다. headless 입력·기하·상태·파일·WASM 빌드 검사와 실제 GUI 검증을 함께 수행한다. 실제 화면과 사용감의 완료 판정은 해당 측정이나 사용자 확인으로 남긴다. [CLI·MCP·skill](AGENT-INTEGRATION.md)은 이번 두 작업 바깥의 보관된 후속 계획이다.
