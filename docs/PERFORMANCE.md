# 스크롤 성능 개선 계획

2026-10-22 계획, 2026-10-23 실행 갱신. 사용자가 보고한 **스크롤 버벅임**을 첫 대상으로 삼는다. 현재 기능 기준선을 유지하면서 입력부터 화면 표시까지 지연이 생기는 경로를 줄인다. 아래 목표 수치는 실측 결과가 아니다.

첫 수정은 [서식 있는 Text의 휠 입력 대기 제거](analysis/0208-scroll-input-backlog.md)다. 한 프레임에 한 개씩만 전달하던 휠 구간을 같은 native 묶음에서 처리한다. 실제 App의 전체 이동량과 편집·계산·이력 불변을 확인했다. 렌더러 디더링 on/off 비교에서는 개선 근거가 없어 제품 설정을 유지했다. 나머지 표시 지연의 완료 판정은 아래 기준을 따른다.

GUI 허용 후 [Windows 실제 창 비교](analysis/0209-windows-native-software-rendering.md)에서 DX12 CPU 어댑터 선택을 확인했다. 전체 App의 UI 중앙값은 약1ms지만 native 프레임 시작 간격은 약219ms였고, 빈 화면도 약63ms였다. latency2·AutoNoVsync는 해결 근거가 없었다. 이 software/원격 환경의 렌더링 대체 경로를 우선 검증한다. 전체 스크롤 지연 해결은 아직 미완료다.

## 먼저 확인할 경로

스크롤 입력 수신 → 이벤트 처리 → 가시 영역 판정 → 영역 준비·조판 → paint·tessellation → texture 전송·GPU 작업 → 화면 표시를 구분한다. 단계별 CPU 시간, GPU 시간, 프레임 간격과 입력 대기를 별도로 기록한다.

[기존 전체 앱 CPU 측정](analysis/0196-whole-app-frame-cost.md)은 제한된 표본에서 짧은 idle·scroll CPU 시간을 보였지만 실제 화면 표시 지연을 측정하지 않았다. [기존 어댑터 조회](analysis/0198-headless-graphics-adapter.md)에는 소프트웨어 렌더링 경로가 있었으나, 실제 앱 창의 선택 어댑터는 확인되지 않았다. 두 기록만으로 현재 버벅임의 원인을 확정하거나 해결됐다고 판정하지 않는다.

측정은 빌드나 다른 무거운 작업과 겹치지 않는 구간에서 반복한다. 상세 계측을 끈 실행도 포함하고, 관찰자 자체의 비용과 문서/화면 내용 차이를 구분한다.

## 비용별 수정 후보

- **반복 준비:** 이미 준비된 영역을 스크롤할 때 XML/ZIP 해석, 계산 입력 생성, 문서·AST 전체 복제, Undo snapshot, 결과 재포맷이 발생하는지 확인한다. 필요 없는 호출을 제거하고 캐시 miss의 실제 이유를 기록한다.
- **가시 영역 처리:** 화면과 가까운 여유 구간만 조판·그리되 문서 전체 데이터와 저장 결과는 유지한다. 영역 위치·높이 인덱스와 조판 캐시를 재사용해 전체 문서 크기만큼 매 프레임 작업하지 않도록 한다. 새 영역 등장 시 높이가 바뀌어 스크롤이 튀는 문제도 검사한다.
- **paint·mesh·글꼴:** 반복 tessellation, 큰 clip 영역, 복잡한 경로, glyph atlas 갱신과 texture 업로드가 지배하는지 확인한다. 텍스트 선명도와 확대/DPI의 올바른 캐시 키를 유지하며 재사용한다.
- **렌더러:** 실제 선택 backend·어댑터와 software/hardware 경로를 먼저 확인한다. 같은 화면·입력으로 backend 차이를 비교한 뒤 설정 또는 구현을 바꾼다.
- **입력·프레임 예약:** wheel 누적량, smooth-scroll, repaint 예약과 입력 큐 지연을 확인한다. 입력 의미를 보존하면서 중복 작업을 묶고 불필요한 연속 repaint를 줄인다.
- **계산과 스크롤의 경합:** 계산 작업의 결과 게시와 UI 동기화가 스크롤을 막는지 확인한다. 입력 중 값·Enter 확정·명시 계산의 기존 경계와 취소 동작을 유지한다.

## 목표와 완료 기준

60Hz 표시 환경에서는 스크롤 중 표시 프레임 간격의 p95가16.7ms 이내인 것을 목표로 삼고,50ms 이상 멈춘 표본은 원인을 확인한다. 이 수치는 목표이며 현재 성능을 뜻하지 않는다. CPU·offscreen GPU·실제 표시 측정은 각각 구분한다.

같은 문서에서 스크롤해도 수식·결과·단위·계산 상태·선택·Undo가 바뀌지 않아야 한다. 반복 스크롤 후 메모리가 계속 증가하거나, 영역이 비거나, 문서 위치가 튀거나, 계산이 불필요하게 제출되는 회귀가 없어야 한다.

Windows와 peets의 Kubuntu26.04에서 release 기준 자료를 남긴다. 사용자는2026-10-23 GUI·스크린샷 금지를 해제했다. headless 입력·상태·CPU·offscreen GPU 검사와 실제 native 창·표시 경로 검증을 함께 사용한다. 실제 표시와 사용감은 해당 구간의 측정 또는 사용자 확인으로 판정하며 headless 숫자로 대체하지 않는다.

완료 산출물은 재현 입력, 지연 원인과 수정, 같은 조건의 전후 자료, 상태/저장 회귀 결과다. 검사 개수나 함수 개수로 부드러움을 판정하지 않는다.
