# 입력 이력의 문서 전체 복제 제거

2026-10-16. GUI·스크린샷·원본 실행 없이 Rust 상태 전이와 headless egui 입력을 검사한다. 이 변경은 원본에 새 기능을 추가하지 않고 기존 Undo 비용을 줄인다.

## 발견한 비용과 변경

`WorksheetApp::page_ui`는 키·텍스트·붙여넣기·IME 이벤트가 있는 프레임마다 변경 전 문서의 모든 영역을 복제했다. 활성 수식 한 개만 편집해도 영역 수와 다른 영역의 텍스트/수식 크기에 비례하는 할당이 발생했다. 포인터를 누르지 않은 일반 영역 입력은 활성 영역과 커서/선택만 기록하는 `DocumentHistory::Region`으로 바꾼다. 새 영역 삽입, 페이지 설정, 영역 이동·삭제 등 구조 변경은 전체 문서 기록을 유지한다. 같은 프레임에 포인터 누름이 있으면 포커스 전환으로 다른 영역이 바뀔 수 있으므로 전체 기록을 사용한다.

영역 기록 복원은 대상 ID만 교체하며 다른 편집기·영역 크기 cache를 유지한다. 전체 기록 복원은 이전처럼 문서 전체를 복원한다. Undo/Redo의 역방향 기록은 전체 상태로 보관하므로 두 기록 형식을 섞어도 구조 변경 순서를 되돌릴 수 있다. 원본 archive와 저장 계산 cache는 이력에 복제하지 않는다. 활성 편집기의 내부 이력을 재귀적으로 복제하지 않고 커서와 실제 트리만 보관한다.

인쇄 snapshot도 원본 ZIP·저장 계산 원시 자료·편집기 Undo 이력을 복제하지 않는다. 인쇄에 필요한 문서 표현과 계산된 표시, readonly 편집기만 worker로 넘긴다. PDF 경로는 별도의 [벡터 출력](0049-vector-pdf-output.md)을 사용한다.

## 검증 범위

`typing_history_retains_only_the_active_region_and_preserves_other_state`는 4,000개 영역에서 입력 이력이 실제 한 영역인지 확인하고 Undo/Redo 뒤 나머지 3,999개 영역·ID·편집 포커스를 대조한다. `region_and_structural_history_can_be_undone_and_redone_in_order`는 영역 편집과 구조 삽입의 혼합 이력을 검사한다. 기존 수식 커서·텍스트 선택·계산 확정 경계 회귀도 유지한다.

`benchmark_typing_history_full_document_versus_region`은 같은 프로세스에서 100/1,000/4,000개 영역과 1,000회 이력 캡처의 이전 전체 복제와 새 영역 복제를 비교한다. `benchmark_saved_worksheet_idle_and_pointer_hold`는 12×12 저장 결과를 가진 문서의 120회 idle/포인터 유지 프레임을 별도로 측정한다. 둘 다 GPU·창 시스템·운영체제 입력 지연은 측정하지 않으며 실제 사용감 전체가 해결됐다는 근거로 삼지 않는다. 최종 수치와 두 OS 검증은 [CONFORMANCE](../CONFORMANCE.md)에 기록한다.

Windows release의 같은 실행 파일에서 측정한 1,000회 이력 캡처는 다음과 같다. 영역마다 같은 문구를 16회 반복한 텍스트를 넣고 첫 영역을 활성화했다. 이 수치는 이력 캡처만의 비용이며 전체 프레임 속도 향상 배수가 아니다.

| 영역 수 | 이전 전체 복제 | 새 활성 영역 복제 |
| ---: | ---: | ---: |
| 100 | 9,241 μs | 160 μs |
| 1,000 | 127,276 μs | 212 μs |
| 4,000 | 1,415,743 μs | 132 μs |

같은 시점 4,000개 저장 행렬의 120프레임은 idle 159,147 μs, 포인터 유지 167,350 μs였다. 수정 전 163,386/155,338 μs와 비교하면 이 변경으로 idle 시간이 일관되게 줄었다고 말할 수 없다. 키 입력이 없는 idle은 원래도 해당 전체 복제를 수행하지 않으므로 측정 범위를 구분한다. 로그는 ignored `artifacts/rea/typing-history-performance-20261016.log`와 `worksheet-performance-{baseline,region-history}-20261016*.log`에 보존했다.

큰 단일 수식의 편집기 arena 복제, 보이는 수식의 결과/레이아웃 비교, 전체 영역 위치 스캔은 남아 있다. 부하 종류를 구분하지 않고 GPU/backend를 임의로 바꾸지 않는다.
