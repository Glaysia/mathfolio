# Rust 공통 화면의 첫 UI/UX 개편

2026-10-23. Excalidraw처럼 문서 중심의 화면으로 개선하라는 사용자 요청을 반영한다. 독립판에 웹 엔진을 추가하지 않으며, 플러그인은 별도 저장소에서 개발한다. 이번 구현은 네이티브 UI 개편과 WASM을 고려한 경계 분리다. 전체 앱의 WASM 빌드·브라우저 실행·Obsidian/VS Code 내장 완료를 뜻하지 않는다.

## 화면과 동작

- 상시 표시하던 큰 Prime 리본을 간결한 파일·문서명·저장·Undo/Redo 헤더와 수식·텍스트·표·도표·풀이·계산 도구로 바꿨다. 작은 container에서는 헤더를 줄이고 도구는 가로 스크롤한다.
- `전체 도구`를 열면 기존 열 개 분류와 구현된 명령에 계속 접근할 수 있다. 숨김 도구가 사라진 기능이 되지 않게 기존 명령 핸들러와 활성 조건을 재사용한다. Ctrl+F1은 기존 도구 모음 접기 의미를 유지한다.
- 명시적으로 열고 닫는 속성 패널에 선택 수식의 결과 형식·자릿수·복소수·글꼴·행렬 인덱스, 텍스트 선택의 강조·크기·색·문단 맞춤, 도표 설정을 연결했다. 숫자 입력은 Enter/입력 종료 때 적용하며 단순 편집 알림을 서식 변경으로 게시하지 않는다.
- F1과 `명령 검색`에서 명령·기존 키·문맥·예제·비활성 이유를 검색한다. 도움말이나 속성 입력이 키를 소유하면 문서의 전역 명령과 편집 확정을 실행하지 않는다. 도움말을 닫은 뒤 원래 편집으로 돌아간다.
- 밝은/어두운 테마·여백·모서리·색을 공통 토큰으로 정리했다. 원본 문서의 종이·글자·표·결과 색과 PDF 출력은 UI 테마와 분리한다. 기존 단축키는 바꾸지 않는다. Ctrl+-는 문자 아래첨자, Ctrl+Y는 Redo이며 Ctrl+Shift+Z는 기존 수식 입력 의미를 유지한다.

이번 검색 catalog는 주요 명령의 안내이며 모든 매개변수 조합을 전부 나열하지 않는다. 함수·단위·기호·임계값 등 상세 옵션은 전체 도구의 기존 메뉴에 남아 있다. 미지원 원본 명령을 지원으로 바꾸거나 새 계산 기능을 추가한 것은 아니다.

## WASM을 고려한 구조

`mathcraft-app` 실행 진입점을 얇은 `main.rs`와 `mathcraft_ui` 라이브러리로 분리했다. UI·명령 안내·테마는 Rust egui 구현 하나다. OS 글꼴 탐색은 `native_fonts`로 옮기고 공통 `configure_surface(ctx, fonts, theme)`는 호스트가 공급한 글꼴을 사용한다. 네이티브의 기존 글꼴 선택 순서와 동봉 STIX를 유지한다.

파일 선택·직접 IO·창 lifecycle·인쇄·계산 thread를 모두 분리한 것은 아니다. public WASM 세션 API·Worker·TS SDK와 두 호스트 실행은 [구조 계획](../NATIVE-WASM.md)의 후속 작업이다. 이번 코드에는 Obsidian/VS Code 플러그인 구현이나 JS/TS 실행 엔진이 없다.

## 검증 범위

새 application-level 테스트는 도움말 입력/단축키의 문서·계산 격리, 속성 숫자의 확정 경계, 기존 키 설명, 테마/패널 토글의 문서 불변, 350/600/1180px 헤더 배치를 검사한다. 기존 텍스트 서식의 실제 포인터 테스트는 `전체 도구`를 연 뒤 같은 명령과 단일 Undo 경계를 확인한다.

네이티브의 입력·계산·MCDX·인쇄/PDF 회귀는 기존 검사에 연결한다. Windows와 peets의 같은 소스 자료, release 실제 창의 화면·스크롤 관찰은 `artifacts/rea/ui-modernization-20261023/`에 보존한다. native-profile의 화면 시나리오 선택은 진단 빌드에만 존재하며 일반 제품 실행에는 포함하지 않는다.

Windows fmt·workspace/all-targets/native-profile Clippy·workspace/egui-winit 테스트·기존 참조 계산을 통과했다. 일반 테스트 2,185개, ignored 105개다. peets에서는 같은 코드의 `scripts/check.sh`로 fmt·Clippy·workspace/egui-winit 테스트·개발 빌드를 통과했다. 일반 테스트 2,186개, ignored 103개다. ignored는 실행하지 않았으며 Linux GUI 사용감을 확인한 것은 아니다. 소스 archive SHA256은 `5afbdc67fc1beefd3eca4c5b9763c9e763708746a0b26af82fb0c64e74254845`이고 이후 문서 갱신과 코드 변경 여부를 구분한다.

## 실제 Windows 창과 성능

기본 화면·속성 패널·어두운 테마·전체 도구·검색 도움말을 실제 native 실행체의 screenshot으로 확인했다. 처음 발견한 Undo/Redo 글리프 누락을 기존 벡터 아이콘으로 수정했다. OS 화면 캡처·포인터 자동화 성공을 뜻하지 않으며, 자체 native-profile의 실제 창/surface·in-app capture를 사용했다. 입력 조작은 위 application-level 상태/포인터 테스트로 검증했다.

기존 [0211 표시 경로](0211-windows-scroll-renderer-fix.md)는 바꾸지 않았다. 같은 Windows·1180×900·PPP 1·CPU surface·1015 문서·동일 합성 휠에서 각각 112프레임을 실행하고 17~96번 80프레임을 비교했다. 새 화면의 종이 노출 범위가 더 넓으므로 그리는 문서 내용은 완전히 같지 않다.

| 최종 비교 조건 | 중앙값 | p95 | 최대 |
| --- | ---: | ---: | ---: |
| 기존 UI, 같은 회차 | 5.687ms | 7.164ms | 7.868ms |
| 새 기본 UI, 100% | 6.928ms | 8.558ms | 9.667ms |
| 새 기본 UI, 100% 반복 | 6.540ms | 8.063ms | 8.853ms |
| 새 기본 UI, 200% | 4.302ms | 6.029ms | 6.928ms |
| 새 기본 UI, 1016 100% | 6.444ms | 7.994ms | 9.270ms |
| 수식 속성 패널 | 6.660ms | 8.281ms | 9.446ms |
| 어두운 테마·속성 | 6.597ms | 8.789ms | 14.955ms |
| 검색 도움말 열린 상태 | 12.874ms | 15.072ms | 66.775ms |

표의 p95는 기존 진단과 같은 정렬 표본 76번째 값이다. 모든 실행에서 source·저장 결과·계산 제출 generation·Undo/Redo·dirty 불변 검사를 통과했다. 입력·실행체 SHA, 초기 수정 과정의 관찰도 `comparison.json`에 보존한다.

기본 UI 반복은 같은 회차 기준보다 p95가 약 12.5~19.5% 높았다. 표시 영역과 함께 평균 visible 영역 수는 23.125에서 24.21~24.31로, raster 중앙값은 4.064ms에서 4.65~4.71ms로 늘었다. UI 처리 중앙값은 0.391ms에서 0.44~0.54ms였다. 늘어난 문서 노출이 추가 비용의 전부라는 인과 검증은 하지 않았고, 계획의 10% 회귀 관찰선을 넘은 자료로 명시한다. 모든 조건의 비용이 기존과 같다는 완료 판정은 보류한다. 주 계산서 스크롤은 이 표본에서 16.7ms 목표 안이지만, 도움말의 49번째 프레임에 66.775ms 간격 한 번이 있으며 scheduling/표시 지연의 세부 원인은 분리되지 않았다.

이는 실제 창의 native raw-input 시작 간격이며 모니터 scanout FPS·OS 입력 도착 지연 또는 모든 문서의 성능 보장이 아니다. 이번 변경의 사용감은 사용자 확인이 남아 있다. WASM·두 플러그인의 실제 실행 검증도 후속 범위다.
