# 입력 초안과 계산 확정 분리

2026-10-16. 원본 계약은 [0042](0042-edit-commit-contract.md), 사용자 출력 비교는 [0043](0043-pdf-output-comparison.md)를 따른다. 앱 GUI·스크린샷·원본 런타임 없이 구현한다.

이전 앱은 수식 위젯의 `changed` 응답마다 전체 문서 MathML을 구성하고 계산기 update·자동 계산을 요청했다. 백그라운드 worker가 있어도 입력 중 불필요한 준비·취소·재실행이 반복되는 구조였다. 이제 일반 문자·숫자·단위 편집은 AST·커서·Undo·dirty 상태와 현재 영역의 미확정 상태만 갱신한다. 매 키에 워크시트 소스를 구성하거나 worker 작업을 제출하지 않는다. 마지막 확정 계산값과 후속 도표는 유지한다.

워크시트의 일반 Enter, 빈 종이 클릭, 다른 영역으로 이동해 활성 편집을 마치는 경계에서 계산에 전달한다. 수식/프로그램 내부에서 소비한 Enter·행렬 Tab·IME 조합 입력은 이 경계를 통과하지 않는다. 리본에서 수식 구조·원자·라벨·행렬을 편집하는 명령도 초안으로 남긴다. `=` 명시 평가와 Ctrl+F5는 현재 초안을 확정한다. F5는 실제 보이는 활성 편집을 확정하며 화면 밖 초안은 마지막 확정 입력 snapshot과 분리해 유지한다. Auto ON도 초안을 암묵 확정하지 않고 마지막 확정 입력으로 계산한다. cold 문서는 첫 편집 전에 snapshot을 한 번 구성하되 계산기를 실행하지 않는다. 자동 모드의 `=`는 활성 영역 강제 계산과 후속 자동 범위를 한 worker 요청에 묶고 명시 요청으로 분류해 Auto OFF에 지워지지 않게 한다.

수동 모드에서 편집을 확정하면 소스 준비·무효화만 하고 이전 결과를 Pending 상태로 유지한다. 저장은 편집을 확정하지만 전체 계산 완료를 기다리는 명령으로 바꾸지 않는다. 미확정 내용의 snapshot을 저장할 경우에도 이전 종속 결과를 새 입력의 Synchronized 결과로 기록하지 않는다. 초안 입력 중 도착한 이전 worker 회신은 초안 영역의 Pending 상태를 지우지 않는다.

회귀 검사는 연속 숫자 입력 중 이전 종속 결과 유지, Enter 후 갱신, 영역 밖 클릭과 수동 모드, IME Commit/Undo, 명시 계산, 저장 상태, worker 제출 횟수를 다룬다. 실제 OS IME 후보창·창 전체 focus 상실·모든 원본 제어문과 컨트롤은 검증 범위 밖이다. 문서 Undo snapshot과 현재 수식 자체 조판은 입력 시 여전히 수행한다. 이 변경을 전체 입력 비용의 제거로 설명하지 않는다.

최신 플랫폼 검사 결과는 [CONFORMANCE](../CONFORMANCE.md)에 기록한다. 제공된 PDF의 표시 공백은 이 편집 확정 변경과 별도다. Percent·극형식의 후속 연결은 [0047](0047-result-formatting-integration.md)을 따르며 표·색상·벡터 PDF는 남아 있다.
