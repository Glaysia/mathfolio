# Commit preparation design audit

2026-10-19. Read-only audit of r109, followed by an approved bounded typed-source candidate. This document separates a proposal from measured performance. The existing reference archive `d537366ab6fa8760982709d99f82a0bc9f357ed7f243e0d7411866ffdc1057d3` and app harness `b11903f67869d2a07d420c0aa0c0214a94d40e2e37c99de8962b035ebe080bd0` are preserved. No GUI/original runtime is used.

## Current blocking work

Final r109 4k Text Enter prepares about 40.8–40.9 ms: signature 7.2–7.6 ms, validation .17 ms, raw serialization 7.2 ms, worksheet 22.4–23.1 ms and display 2.8–3.6 ms (column medians are independent). Matrix prepares about 28 ms; originals about 3 ms. Source: `program-insertion-open-input-phase-summary-20261019.json`. R105 already removed full display DOM by projecting eager trees from the labeller's parsed contexts; repeating that optimization is not available now.

`calculation_changed`/`calculate_command_with_active` calls `refresh_calculation_input` on the UI thread before `dispatch_background`. `prepare_input` computes exact presentation-v1 JSON/SHA, serializes cached typed trees, sorts/labels generated XML, creates eager display trees/maps and geometry. The worker receives only an already prepared XML Arc. It then parses calculator state, executes ordered active/prefix/full requests and plots. Existing `worker_remaining_us` excludes work concurrent with Enter, so it must not be added to Enter medians as a full latency measure.

## Candidate A: typed fragments with shared label policy

The dominant avoidable round trip is typed tree → raw XML → label DOM/patch → display tree. The first bounded candidate keeps the original raw serialization for its proven bytes/error ordering, but replaces eligible fragment DOM parsing, scope walks, patching and display decoding with a shared identifier policy, sparse AST child-path plan and the existing serializer. It deliberately still pays a labelled serialization pass. A meaningful cold Enter reduction is plausible, but neither 16 ms nor a particular saving is established until measured.

### API and ownership

- A public immutable `TypedMathml` proof has private tree/raw-XML fields and can only be constructed through the existing `tree_to_mathml` validation/serializer. It replaces the app's existing duplicated `SerializedMath` tree/XML snapshot; it does not add another persistent tree copy. A matching raw XML check prevents attaching a stale proof to another statement. Pointer identity alone is never the guard.
- A new optional typed builder entry accepts the ordinary ordered region tuples plus proofs by ID. Legacy string/metadata/projection APIs retain their exact paths. Raw opaque, table and solveblock XML retains DOM handling.
- `resolve_identifier_label` contains the policy currently inside `label_parsed_fragment`: explicit labels versus None/contextual; declaration; structural child-subtree constraints; nearest binder/local overlay; builtin-call role and environment/catalog lookup; dependency observation. DOM and typed adapters supply facts to the same policy. The DOM adapter still owns its existing binder/context discovery.
- A sparse plan is keyed by actual AST child indices, not matching traversal positions. The serializer follows its existing child indices, including `row * cols + col` when emitting column-major matrix XML. No AST/XML preorder zip is used. Applying the plan to a cloned tree creates the display projection; it is moved into the app and never retained in the fragment cache.
- The existing `Fragment` source, dependency, declaration-effect and labelled-string payload/budget remain. Cache hits keep existing exact source/environment guards. No new global tree cache or label laziness is introduced.

### Initial accepted subset and fallbacks

Initial fast eligibility is intentionally plain: direct named define/globalDefine targets, eval/unit-override, scalar literals, ordinary unary/binary arithmetic, groups, matrices, simple named calls and index/row/column operands. Function definitions, all program/control BODY forms, calculus/lambda binders and symbolic commands stay on the raw-DOM path until independent canonicalization/scope oracles exist. They are not silently flattened or approximated.

Typed forced-label context follows child edges. Eval's unit override forces UNIT; an index/row/column operand interrupts that inherited constraint, while its base preserves the enclosing context. Direct declaration labels use SYSTEM only for an unsubscripted system name immediately under define/globalDefine. No declaration effect enters the environment until the fragment has been labelled. The existing global prepass and geometric order remain authoritative, including raw/typed mixtures and the lexical globalDefine false-positive path. Explicit labels, contextual labels, None `*`/`NONE`, unit names and literal-subscript identities share the same resolver.

Proof construction preserves the original validation/serialization failure before builder processing. XML 1.0-invalid strings and literal CR/attribute-whitespace cases must fall back to XML: a raw serializer can emit literal whitespace that the parser normalizes before label lookup. They must not be interpreted directly with different names/labels. Additional XAML/native attributes remain opaque or take the old parser, and valid typed XAML serialization keeps the existing serializer's exact namespace/attribute order. Display normalization must match the final generated XML parser, including unsubscripted NativeIdentifier with no contextual flag canonicalizing to AnnotatedIdentifier. Near depth/shape uncertainty falls back rather than asserting equivalence.

### Validation and measurement gates

Before adoption compare exact generated XML, every display Result/tree against the complete generated DOM, declaration/environment effects, retained bytes/eviction and first error/cache side effects against the ordinary builder. Cases include cold/warm/changed ID and context, global declarations before/after use, units and builtin calls, explicit/None/contextual labels, Unicode/subscripts/entities, column-major matrix ordering, Eval unit overrides and interrupting index operands, invalid XML/CR/attribute whitespace, unsupported raw XAML, disabled/table/solveblock mixtures, duplicate IDs/NaN coordinates/signed zero and 8 MiB output budget. Programs/functions remain explicit fallback assertions. Actual captured 4k/matrix/1015/1016 inputs and app full-DOM/lazy F5/print oracles remain required.

Measure the same actual save/fresh-open six fixtures and six event modes with frozen before/after harnesses, five alternating recorder-off runs. Report whole Enter, per-run Text+Enter and worksheet+display sums; a shifted phase is not a saving. Record cold/warm builder cost, transient plan/projection bytes and retained cache payload; these are not RSS. Keep old fallback and candidate artifacts even on regression. If second serialization dominates, a later fused serializer/identifier-range trace may remove that repetition, but that is a separate measured change, not assumed in this candidate.

Owned implementation files: compat `editor_bridge.rs` helper/serializer/DOM-policy region, `editor_bridge/worksheet_cache.rs`, new typed helper/tests; app `worksheet_ui/edit_commit.rs` proof/API integration and its input tests. No change is required to root's calculation operators, formula input/paint or ribbon functionality.

### Differential and bounded-memory evidence

Eight new normal differential tests pass. They compare exact source, optional decoded Result/tree, dependency sets, declaration effects and entry payload against the existing DOM builder, including cold/warm context changes, order, deletion/new IDs, direct/system/None/contextual/explicit labels, literal subscripts/XAML/Unicode/entities, builtin calls, unit inheritance interrupted by index/row/column, every eligible ordinary editor variant and column-major matrix identity. Functions/programs, depth uncertainty, proof mismatch and XML normalization cases explicitly use fallback. Invalid structural strings retain the original serializer error. Ordered malformed XML/identifier errors preserve partial cache effects. A 750-region long-name case reaches both the unchanged 8 MiB output error and 32 MiB payload eviction; the error and remaining exact entries/bytes match the DOM oracle.

The ignored actual-capture oracle compares every projected tree with a full generated worksheet DOM and checks cold/warm source and retained payload. All six pass. Exact eligible proof counts are 4,000/4,000 for each scalar capture, 100/100 for each matrix capture and 79/80 for each original; the remaining original region stays raw. Final compat library tests are 69 passed/8 ignored, and compat plus app all-target Clippy with `-D warnings` passes. Existing app workspace tests were separately exercised by the root before final source freeze; final integration records their authoritative count.

`TypedMathml` replaces the existing retained serialized tree/string tuple with one immutable Arc-owned proof; it adds the Arc allocation/header and eligibility flag, not a second persistent AST. The per-Enter proof map temporarily holds Arc references. A sparse plan/replacement identifier strings live only for the current fragment, and the projected tree is moved into the existing app display map. No projected tree or plan is stored in `WorksheetXmlCache`; its exact payload and 32 MiB reset remain unchanged. These observations bound ownership, not allocator peak/RSS. The existing atom/tree limits and conservative typed depth cutoff apply; large/deeper/unsupported forms retain the ordinary DOM acceptance/error path. The second labelled serialization and projection allocation remain work, so the measured builder reduction does not imply their elimination.

## Candidate B: worker-side preparation, deferred for this batch

Moving preparation to a worker is a real ownership/protocol change, not replacing one submit argument. It can reduce UI Enter time only after measuring raw snapshot capture, editor validation, pending bookkeeping, queue submission and later reply adoption. The 40 ms work still exists; queue wait, preparation, calculator update/evaluation/plots and adoption must all be measured, with submission-to-ready and submission-to-settled latency plus worker CPU/residual.

Concrete entry: background-enabled branch before `refresh_calculation_input`, with an immutable owned committed calculation snapshot (regions/settings/native bytes plus editor revision/fault metadata, never borrowed Editor/egui state). Worker-owned preparation cache executes the same pure preparation function. Direct/synchronous tests retain the existing path. Requests cannot be finalized before preparation because active/through selection currently filters by `input.region_ids`; a frozen command plan must carry the UI's active/visible bound/force/order and resolve it against the prepared result. Blanket full-worksheet requests would change semantics.

A correct protocol needs distinct document epoch, immutable committed-source version, submission generation and label-view version. The worker's existing one queued source, generation monotonicity, epoch gate and nonjoining Drop are useful, but preparation must join those gates. A `Prepared` message is distinct from calculation completion so eager complete-worksheet labels can be installed even while long evaluation runs. Preparation failure is distinct from Stop; it must not revive stale bindings. Cancelling older work must not publish partial cache/labels. The latest stopped/manual snapshot still prepares pending state with no execution, as current worker cancel/pause contracts require. Parsing currently lacks fine-grained cancellation; a bounded in-progress parse cannot be assumed instantly interruptible.

Important unresolved contract: current Enter installs all label trees on the same UI frame, and `print_snapshot` immediately clones that map. Async preparation cannot preserve this exact availability while moving all of it off the UI. A new print preparation barrier or a synchronous exact fallback would be required; old labels must not silently style a newer print snapshot. F5 during a draft must keep the old committed snapshot and must not install its isolated labels over the live draft map. A reply arriving after a new draft/commit must be gated separately for source, display labels and result pending state. Per-region shared trees or explicit label-version/delta acknowledgement would be needed to preserve warm cache validity without unbounded duplicated trees. This is materially wider than Candidate A.

Other required invariants: open/new still perform zero evaluation; Auto OFF pauses queued automatic requests but leaves explicit F5/equals/full calculation executable; Stop keeps old values and moves to Manual while newest pending state remains; text-only changes do not replace explicit work already in flight; disabled regions, table drafts, plots and malformed source retain current fault/pending behavior. Save must not mark unprepared values synchronized. Reset/open/new and Drop must reject stale prepared and calculated replies without joining the worker. Snapshot/native bytes must have bounded ownership across current/running/queued versions, with no weak pointer-only identity guard.

Required gated tests would pause before snapshot preparation, after Prepared, during calculation and before adoption: rapid commits, draft+offscreen F5, AutoOFF with queued automatic versus explicit work, Stop before/during preparation, same-source explicit commands, text-only mutation, reset/reused IDs, print/save before labels ready, table/solveblock faults, large native archive and worker termination. Existing worker/background/lazy-baseline tests provide the oracles but do not already cover the new protocol. Source files would include `calculation_worker.rs`, background dispatch/state, extracted pure preparation/snapshot types, edit_commit command entry, worksheet command planning, print/save barriers and extensive tests. Therefore B is deferred here rather than weakening same-frame labels/print/F5 contracts to claim a 16 ms target.
