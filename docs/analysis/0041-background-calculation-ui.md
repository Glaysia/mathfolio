# 백그라운드 계산과 중지·재개 통합

2026-10-16. 원본 정적 계약은 [0039](0039-calculation-queue-and-cancellation.md), 엔진 취소·rollback은 [0040](0040-calculation-cancellation-engine.md)를 따른다. GUI·스크린샷·원본 프로세스 없이 구현했다.

이전 데스크톱 앱은 수식 입력과 F5/Ctrl+F5 명령에서 계산기를 UI 스레드에 직접 호출했다. 가시 영역 조판을 캐시해도 긴 프로그램·행렬·풀이 계산 동안 UI가 돌아오지 않는 구조였다. 데스크톱 실행은 이제 영속 계산 worker를 만들고 소스 준비·계산·도표 표본 평가를 그 스레드에서 수행한다. 기존 직접 계산 API는 동기 회귀·CLI에 유지한다. 비동기 통합도 별도 headless 테스트로 검증한다.

UI는 MathML 입력을 구성하고 요청의 세대 번호와 함께 전달한다. 대기 소스는 최신 하나만 보관하며 이전 실행에는 협력 취소를 요청한다. 완료 결과는 `try_recv`로 읽고 알림은 repaint callback을 사용한다. UI에서 결과를 기다리거나 계산 스레드를 join하지 않는다. 문서를 열거나 새 문서를 만들면 epoch를 바꾸고 이전 문서의 결과·바인딩을 버린다. 이 전역 세대/최신 소스 정책은 원본의 위치별 의존성 queue를 그대로 복제한 것이 아니라 오래된 답이 새 수식에 붙지 않게 하는 독립 안전 정책이다.

F5는 보이는 활성 영역을 먼저 강제 계산하고 가시 경계까지의 요청을 순서대로 worker에 보낸다. Ctrl+F5는 전체 강제 계산한다. 도표는 같은 worker의 계산된 문맥을 사용한다. 활성 정의를 강제 갱신하면 범위 안 후속 도표도 다시 계산한다. 수동 편집은 입력 준비/무효화만 수행하고 식을 실행하지 않는다. 저장된 결과는 계속 표시하며 Pending 상태만 별도로 유지한다.

새 소스를 준비 중일 때 UI는 우선 활성 계산 영역을 보수적으로 Pending 표시한다. worker의 정확한 입력 prefix 상태가 도착하면 계산된 앞 영역은 다시 동기화한다. 이 임시 표시와 순서 기반 downstream 무효화는 원본 정밀 의존성 그래프 전체가 아니다. 수식의 MathML 구성과 문서 Undo snapshot은 아직 UI 스레드에서 수행한다.

계산 리본의 **모든 계산 중지**는 진행 중일 때 활성화하며 자동 계산을 끄고 현재 작업을 취소한다. 중지된 영역은 계산 오류로 게시하지 않는다. 완료된 앞 영역·전역 정의·이전 표시값을 보존하고 미완료만 Pending으로 남긴다. 자동 계산을 다시 켜면 미계산 구간을 이어서 처리한다. 수동 모드의 F5/Ctrl+F5도 기존 범위대로 동작한다. 원본 근거가 없는 별도 Resume 버튼이나 Stop 단축키는 추가하지 않았다.

자동 계산 체크 해제만으로 진행 중인 작업을 강제 취소하지 않는다. 이는 원본의 Auto OFF와 StopWorkers가 별도 경로인 점을 따른다. 아직 시작하지 않은 자동 요청은 계산·도표 실행을 보류하고 소스 준비만 한다. 대기 중인 명시 F5/Ctrl+F5 요청은 유지한다. 이미 시작한 요청 묶음의 결과는 수용한다. 원본 queue가 영역 사이에서 Auto OFF를 처리하는 모든 경계까지 복원한 것은 아니다.

출력 reply에는 최종 계산 snapshot 하나와 모든 중간 요청의 실행 ID를 합쳐 전달한다. UI는 현재 세대의 답만 수용하고 실제로 완료된 도표만 저장 표현을 교체한다. 원본처럼 각 영역의 완료 즉시 화면에 게시하는 단계는 아직 구현하지 않았다. 중지된 최신 대기 소스는 계산 없이 준비해 Pending 상태를 확정할 수 있다. 수동 모드에서 텍스트 삭제·복제·이동처럼 계산 소스와 활성 계산 서명이 동일한 편집은 새 준비 요청으로 기존 명시 계산을 교체하지 않는다. XML 파싱 등 단일 라이브러리 호출의 도중에는 즉시 강제 중단을 보장하지 않는다. 긴 계산의 내부 협력 취소 지점은 [0040](0040-calculation-cancellation-engine.md)에 기록했다.

회귀는 worker의 최신 요청 coalescing, 중지된 대기 입력·이전 값·재개, 문서 reset과 구 답 차단, 도표 문맥 재사용, UI에서 join하지 않는 종료를 검사한다. 앱 통합에서는 최신 입력만 표시, 수동 준비의 실행 0, Stop→MANUAL→Auto 재개, Auto OFF의 대기 자동/명시 요청 구분, 텍스트 편집 중 명시 전체 계산 보존, 새 문서의 구 답 차단, 활성 정의와 후속 도표의 동일 범위 갱신을 검사한다. 경합은 callback gate로 순서를 고정하며 임의 sleep에 의존하지 않는다. 전체 Windows/Linux 검증 결과는 [CONFORMANCE](../CONFORMANCE.md)에 기록한다.

후속 [0044](0044-edit-commit-implementation.md)는 일반 타이핑을 계산 입력 준비와 분리한다. 새 소스의 worker 제출은 일반 Enter·영역 이탈·명시 계산 등 확정 경계에서 수행한다. 위의 최신 소스 교체는 각 키 입력마다 발생하는 정책을 뜻하지 않는다.
