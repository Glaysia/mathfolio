# Mathcad 12 programming semantics: shipped evidence and independent subset

No original application, COM session, GUI, screenshot, or original evaluator was executed for this investigation. The interpreter is independently written Rust. Its tests are synthetic fixtures, not captured Mathcad results. This establishes a bounded implementation contract, not execution parity.

## Implemented subset

`crates/mathcraft-compat/src/program.rs` parses native Math50 programs with namespace, attribute, child-count, branch-kind and nesting validation. Parent Expression dispatch integrates Program and Logic. Execution clones worksheet/function scope, supports scalar-name local assignment, lazy if/elseif/alsoif/else, for, while, break, continue, return, and final calculated value. A return propagates through nested loops; loop control affects the innermost loop. Program bodies in user-defined functions use captured worksheet scope and formal parameters. Automatic `*` references resolve to VARIABLE names declared locally by that program; first local initializers can read the corresponding worksheet binding. This narrow alias policy does not implement general contextual labeling.

Boolean scalar operators and/or/xor/not return 0/1. Equality supports complex scalars with matching dimensions; ordering currently requires real scalars. For accepts scalar, range and one-dimensional row/column matrix inputs. Local assignments retain matrices; local range assignment is rejected until native materialization semantics are established.

## Explicit independent policies and missing behavior

Execution has a default100,000 tick budget, max128 nesting depth, max4096 lines per block, max16,384 range elements and max8MiB standalone MathML input. Ticks count statements, tests and loop steps; this is not global accounting for every nested parent evaluator operation or recursive user-function invocation. Budget/error identifiers are project policy. A block preserves its last produced value across no-output branches/iterations; a program producing no value reports `program_no_value`. Exact original empty/unmatched/zero-iteration result behavior remains unverified.

Logical operators are eager here; only branch laziness is established by the inspected help. Comparisons use strict floating-point equality without worksheet tolerance options. Dimension-bearing boolean tests, ordered complex values, array/string comparisons and vectorized comparisons are unsupported. Indexed local assignment, local function/alias definitions, assignment/program side effects in conditional tests, general2D for iteration, try/onerror, and lazy function-shaped `if(cond,x,y)` remain unsupported. This module does not provide program editing UI or preserve unsupported fragments by inventing semantics.

## Validation

`cargo test -p mathcraft-compat --test programming`: 8 tests passed. Tests cover range accumulation, pre-test loops, continue/break/return nesting, elseif laziness, alsoif, scope isolation, worksheet-first shadow initialization, function parameters, automatic local references, complex truth, comparison, bounded infinite loop failure and malformed forms. These confirm this implementation's contract; they do not compare outputs against a running Mathcad instance.

After symbolic dispatch integration, the malformed-program regression also checks that symEval is rejected both as a program line and within a local assignment RHS. This follows the installed `symbolic_evaluation_operator.html` restriction, rather than silently allowing the newly introduced expression kind through the generic numeric program path.
