# Mathcraft 작성 경험의 기준

Mathcraft의 제품 가치는 계산 함수를 많이 제공하는 데 있지 않다. 사용자가 종이에 쓰듯 수식을 작성하고, 구조를 고치고, 단위와 결과를 같은 자리에서 읽으며 생각을 이어갈 수 있어야 한다. 계산 엔진과 문서 형식은 그 작성 흐름을 지탱한다. Mathcad의 이 흐름을 이해하기 위해 REA로 명령 진입점, 편집 모드, 상태 변경과 저장 표현을 추적한다.

원본 내부 구조에서 확인한 사실과 우리가 재구성한 정책을 구분한다. 정적 코드에서 보인 경로를 실제 키보드·IME·화면 동작까지 검증했다고 부르지 않는다. 현재 사용자의 지시에 따라 Windows와 peets 모두 GUI·스크린샷·원본 실행 없이 작업한다.

| 작성 상황 | 지켜야 하는 계약 | 구현과 근거 |
| --- | --- | --- |
| 수식 중간에서 Space로 범위를 넓힌다 | 범위의 방향과 진입 커서를 보존한다. 끝까지 확장하면 원래 커서로 돌아온다. 이동만으로 Undo를 소비하지 않는다. | editor의 scope 상태·이력, [0014](analysis/0014-expression-scope.md) |
| 선택한 부분식에 연산자를 넣는다 | 선택한 쪽에 따라 기존 부분식이 왼쪽 또는 오른쪽 피연산자가 된다. 인접 가지의 ID와 Undo 복원을 유지한다. | 분수·지수·이항 연산의 제한된 subtree 계약, [0014](analysis/0014-expression-scope.md) |
| 선택한 복합식을 문자로 바꾼다 | 선택한 가지를 치환한다. 선택을 암묵적 곱셈의 피연산자로 오인하지 않는다. | formula 입력·치환 테스트, [0017](analysis/0017-contextual-commands.md) |
| 정의 뒤에서 `=`를 누른다 | 정의를 유지하며 RHS를 평가한다. 이미 평가가 있으면 수식 변경 없이 계산을 요청한다. | 문서 변경과 계산 요청을 분리한 입력 결과, [0017](analysis/0017-contextual-commands.md) |
| 결과 단위를 입력한다 | 물리량과 표시 단위를 분리한다. `distance:=2m=cm`의 정의값은 2m이며 표시는 200이다. | 편집→MathML→계산 통합 테스트 |
| 붙여넣기 또는 확정 텍스트를 되돌린다 | 내부의 여러 트리 변형을 사용자 명령 하나로 묶고 이전 선택·커서도 복원한다. | `Editor::edit_group`, [0014](analysis/0014-expression-scope.md), [0017](analysis/0017-contextual-commands.md) |
| 저장 문서를 다시 계산한다 | 명시적 라벨과 이전 계산의 문맥 라벨을 구분한다. 이전 추론을 사용자 지정으로 고정하지 않는다. | 원본 메타데이터 보존·계산용 라벨 처리, [0016](analysis/0016-contextual-labels.md) |
| 계산 상태가 바뀐다 | 계산 중 여부, 결과의 동기화 여부, 결과·오류 payload를 구분한다. 오래된 결과를 새 정답으로 읽지 않는다. | 원본 상태 분석, [0015](analysis/0015-worksheet-feedback.md); 현재 Rust 재계산은 동기식 |

새 기능은 실제 작성 상황 → 필요한 편집 상태 → 원본 근거 → 독립 구현 → 재현 테스트 순서로 추가한다. 함수 목록의 개수나 단위 테스트 통과 수는 UX 완성도를 대신하지 않는다.

부분 피연산자 범위, 원본 전체 키 전이와 우선순위, 행렬 선택, 오류 노드 위치, IME, 드래그·클립보드의 OS 통합은 미완료다. 이번 headless 검증은 Rust 상태 전이·계산·저장을 확인하며, 최종 사용감의 확인은 추후 사용자가 허용한 실기 검증에서 수행한다.

## UI와 작성 흐름 개선 — 2026-10-15

상단 명령을 파일·편집·삽입·보기 메뉴와 짧은 작성 도구막대로 정리했다. 문서는 회색 작업 영역 중앙의 흰 종이로 배치하고 격자 점은 선택적으로 표시한다. 배율은 종이의 별도 입력·그리기 레이어에만 적용하여 메뉴·상태막대·OS 배율을 유지한다. 파일 알림은 상태막대에 표시하여 작성 중 페이지 위치를 밀지 않는다. 이 외형·배치 정책은 독립적인 제품 선택이며 원본 화면과 일치한다고 주장하지 않는다.

수식 영역을 Esc로 선택한 뒤 방향키로 옮기고 Enter로 다시 편집할 수 있다. Tab은 편집 중에는 입력 칸을, 영역 선택 중에는 위치 순서의 영역을 이동한다. Ctrl+Enter로 활성 영역 선택을 전환한다. 우클릭 메뉴에는 편집·영역 복사·잘라내기·복제·삭제를 모았다. 분수·지수·제곱근·절댓값 도구는 현재 피연산자를 보존하며 삽입한다.

문자 안에서는 Shift+방향키와 드래그로 범위를 선택하여 복사·치환·삭제할 수 있다. UTF-16 경계와 부분식 선택을 구분한다. 위·아래 이동은 현재 렌더링된 분수·지수·행렬 입력 칸의 기하를 이용하는 제한된 독립 정책이다. 여러 피연산자를 가로지르는 드래그는 공통 상위 부분식을 선택하며, 원본의 부분 선형 범위를 재현하지는 않는다.

문서 Undo는 수식 arena·커서·선택·scope 및 텍스트 커서를 함께 복원한다. 과거 편집기의 Undo 스택을 다시 복사하지 않는다. IME preedit는 화면 상태로만 유지하고 Commit을 하나의 명령으로 적용하며 후보창 위치에는 종이 배율을 적용한 커서 좌표를 전달한다. 조합 중 Enter가 다음 수식으로 넘어가지 않도록 분리한다. Ctrl+T·Ctrl+Shift+M·Ctrl+Enter는 기존 원본 단축키 자료와 맞춘 진입점이며 F9와 확대 단축키의 전체 원본 문맥은 이번 작업에서 검증하지 않았다.

검증은 실제 창·스크린샷 없이 egui context의 이벤트와 상태를 검사했다. 50%·100%·200% 클릭 좌표, 수식·텍스트 Undo 후 연속 입력, Esc→이동→Enter, 문자 드래그, UTF-16 선택·치환·삭제, IME 임시/확정/취소 입력, 분수·행렬의 수직 이동을 포함한다. 실제 Windows/Linux IME·후보창·마우스 사용감과 전체 화면 외형은 아직 실기 검증하지 않았다.
